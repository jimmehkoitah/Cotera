# LinkedIn HDR logo test — Cotera

Generated by `make-linkedin-hdr-assets.py` at the repo root. Re-run with:

```bash
python3 make-linkedin-hdr-assets.py --out output
```

All icons are 800×800, progressive JPEG, quality 96, 4:4:4 chroma, no alpha.
The purple gradient is held at **SDR white (203 nits, ITU-R BT.2408)** — it is
*not* pushed into HDR. Only the white arrow and the light spilling off it exceed
it. The arrow mask comes from the vector artwork, not from a near-white pixel
threshold, so the boundary is exact and no purple leaks into the HDR region.

---

## Read this first: there are two different HDR bets in this folder

Your instinct that LinkedIn may strip gain maps but preserve ICC profiles is
**correct about survival** — I measured it. But the ICC route carries a cost
that the measurement also exposed. Both encodings are included because they
fail in opposite directions, and uploading both is the only way to settle it.

| | `*-800nits.jpg` (ICC-PQ) | `*-800nits-gainmap.jpg` (gain map) |
|---|---|---|
| Mechanism | 8-bit PQ / BT.2020 + embedded Rec. BT.2100 PQ ICC profile | SDR base + per-pixel gain map (ISO 21496-1 / Ultra HDR) |
| Survives a re-encode | **Yes** — ImageMagick kept it; Pillow kept it when asked | **No** — destroyed by every re-encode tested |
| Browser mechanism for HDR | ICC is colour management; it carries no "absolute luminance" signal | This is the mechanism Chrome/Android/Apple actually use for HDR JPEG |
| If the viewer is not PQ-aware | **Breaks.** Colour-managed → mean luma 18/255, panel `#080924` (near black). Ignored → washed grey, arrow `#b9b9b9` not white | **Degrades cleanly** to the authored SDR image, 0.6/255 from intended |

So: ICC survives the pipeline but has no safe fallback. The gain map has a
perfect fallback but probably won't survive. That is the whole experiment.

**My recommendation** is to lead with the gain-map file, because its worst case
is "a normal, correct logo" while the ICC file's worst case is "a near-black or
grey-washed logo in front of your audience." You designated the ICC 800-nit file
as primary; it is built exactly to your spec and named as you asked. I'd just
rather you saw the tradeoff measured before choosing.

## Upload sequence

Post each on its own, a few minutes apart, and look at every one on an HDR phone
(iPhone 12 or later, recent Pixel/Galaxy) at 60%+ screen brightness in a dim room.

1. `cotera-linkedin-sdr-icon-smaller-tightglow.jpg` — the control. Establishes the baseline.
2. `cotera-linkedin-hdr-icon-smaller-tightglow-800nits-gainmap.jpg` — the proven path.
3. `cotera-linkedin-hdr-icon-smaller-tightglow-800nits.jpg` — the ICC bet.
4. `cotera-linkedin-hdr-icon-smaller-tightglow-1200nits.jpg` — only if 3 worked and you want more.

Keep #1 visible while you look at the others. Judging glow from memory does not
work — the eye adapts in seconds.

## How to compare SDR vs HDR on LinkedIn

The effect is *relative*, so give your eye a reference in the same frame:

- Scroll so the control post and the HDR post are on screen together. The arrow
  in the HDR one should look brighter than the white of the LinkedIn UI itself.
- LinkedIn's own page white is the best reference you have — it is an ordinary
  SDR white, the same 203 nits ceiling everything else obeys.
- If you can only see one at a time, put a white browser tab or a blank note
  beside your phone and compare against that.
- Do not judge on a screenshot. A screenshot is SDR and cannot record the effect
  — it will show them as identical even when the difference is obvious in person.

## Checking whether LinkedIn stripped the profile

Download the processed image back from LinkedIn — open the post, right-click the
image → "Open image in new tab" to get the `media.licdn.com` URL, then:

```bash
curl -sL -o processed.jpg "<the media.licdn.com URL>"
exiftool processed.jpg | grep -iE "profile|color space|encoding|components"
```

Read the result like this:

- **`Profile Description : Rec. ITU-R BT.2100 PQ` still present** → LinkedIn
  preserved the ICC profile. Your hypothesis holds.
- **No ICC block at all** → stripped. The ICC route is dead on this surface.
- **`Profile Description : sRGB ...`** → LinkedIn converted it to sRGB. Worse
  than stripping: the pixels were re-interpreted, so it will look wrong.

For the gain-map file, check instead for the second embedded image:

```bash
exiftool -MPF:all processed.jpg          # expect "Number Of Images : 2"
```

`Number Of Images : 2` means the gain map survived. If MPF is gone, so is the HDR.

Also compare file sizes against this folder — a byte-identical size is a strong
hint LinkedIn served your original file untouched, which is the best case.

## What success looks like

- On an HDR display, the white arrow is visibly brighter than the LinkedIn page
  white around it. It reads as *emitting* rather than as *light grey*.
- The purple gradient looks the same as the control — normal, saturated, not
  washed out and not glowing.
- On an SDR display the image looks completely normal.
- `exiftool` on the downloaded file still shows the PQ profile (or MPF 2 images).

## What failure looks like

- **`Color Space: sRGB` or no profile on the downloaded file** → the HDR signal
  was stripped in transcode. Nothing you do to the source file changes this;
  the surface just doesn't carry HDR.
- **The whole image glows, background included** → the HDR region is too broad.
  Not the case in these files (measured: 5–9% of the frame above SDR white), but
  it is what a luminance-threshold mask does instead of a vector mask.
- **Washed out, grey, low contrast** → PQ values are being read as sRGB. The
  profile is being ignored rather than honoured.
- **Very dark, near-black panel** → PQ is being colour-managed to SDR without
  HDR awareness. This is the specific ICC-PQ failure mode measured above, and it
  is the reason I'd lead with the gain-map file.
- **Identical to the control on an HDR phone** → either the display has no
  headroom available at that brightness, or LinkedIn clamped it. Retry at higher
  screen brightness in a dark room before concluding.

## Also in this folder

`.avif` and `.png` versions of the recommended variant, tagged with real **CICP
9/16** (BT.2020 primaries + ST 2084 PQ) — the mechanism browsers genuinely
honour. LinkedIn won't take these, but they're the ground truth for confirming
your display and browser can show the effect at all. Open them locally first: if
they don't glow on your device, no LinkedIn file will either, and you'll have
saved yourself a confusing test.

`rec2100-pq.icc` is the profile embedded in the ICC files, built from scratch by
`scripts/icc_pq.py` — BT.2020 primaries, a 4096-entry PQ transfer curve, D50 PCS
with Bradford adaptation. Verified with lcms2 and ExifTool.

`manifest.json` lists every file with its encoding and peak luminance.
